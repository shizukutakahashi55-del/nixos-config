# NixOS Configuration

Personal **NixOS** configuration managed with **Nix Flakes** and a modular `.nix` structure.

> **Important:** this configuration currently **does not use Home Manager**.
> Packages, services, and system configuration are managed directly through NixOS modules.
> User-level services, such as Tachidesk/Suwayomi, can also be declared from NixOS using `systemd.user.services`.

This README follows the general NixOS configuration and installation workflow described in the
[official NixOS Manual](https://nixos.org/manual/nixos/stable/).

# 🧱 Hardware

## `hardware-configuration.nix`

This file is generated by NixOS and contains hardware-specific information such as:

- filesystem UUIDs
- mounted filesystems
- swap devices
- detected kernel modules
- CPU-specific settings
- the detected system platform

The NixOS Manual notes that `hardware-configuration.nix` is generated by `nixos-generate-config` and may be overwritten by future invocations. It should therefore be treated as **machine-specific generated configuration**, not as a general-purpose hardware module.

### Copying the hardware configuration into these dotfiles

When setting up this repository on an existing NixOS installation, first generate or update the hardware configuration:

```bash
sudo nixos-generate-config
```

This generates:

```text
/etc/nixos/hardware-configuration.nix
```

Copy that generated file into the root of these dotfiles:

```bash
cp /etc/nixos/hardware-configuration.nix ./hardware-configuration.nix
```

Run the command from the root of this repository.

The final structure should contain:

```text
nixos-config/
├── hardware-configuration.nix
├── configuration.nix
├── flake.nix
└── modules/
```

If you are performing a **fresh installation**, the official NixOS workflow can generate the configuration for the mounted target system with:

```bash
sudo nixos-generate-config --root /mnt
```

The generated hardware configuration will then be located under:

```text
/mnt/etc/nixos/hardware-configuration.nix
```

Copy it into the dotfiles repository before installing from the flake.

> **Do not blindly reuse the `hardware-configuration.nix` from another machine.**
> Filesystem UUIDs, disk layouts, swap devices, kernel modules, and other hardware details may be different.

# 📖 Suwayomi / Tachidesk

## `modules/programs/suwayomi.nix`

Suwayomi is manually pinned to:

```text
v2.3.2243
```

using an overlay that downloads the official `.jar` release from GitHub.

The configuration currently **does not use `services.suwayomi-server`** as a system service.

Instead, the server is declared as a **user-level systemd service**:

```text
systemd.user.services.tachidesk
```

This keeps the server stopped until it is needed.

### Commands

```bash
tachidesk start
tachidesk stop
tachidesk restart
tachidesk status
```

You can also inspect the service directly:

```bash
systemctl --user status tachidesk.service
```

The service has no `wantedBy`, so it **does not start automatically when the system boots**.

When running, Suwayomi is normally available at:

```text
http://localhost:4567
```

> The configuration is prepared for a future Rofi launcher/toggle that can start and stop Suwayomi directly from the desktop.

# 🚀 Installation

The following workflow assumes that NixOS has already been installed and that this repository will become the system's flake-based configuration.

For a complete fresh installation, follow the official NixOS installation manual first:

<https://nixos.org/manual/nixos/stable/>

## 1. Clone the repository

```bash
git clone <REPOSITORY_URL>
cd nixos-config
```

If the repository is already cloned:

```bash
cd nixos-config
```

---

## 2. Generate the hardware configuration

On an existing NixOS installation:

```bash
sudo nixos-generate-config
```

Then copy the generated hardware configuration from `/etc/nixos` into this repository:

```bash
cp /etc/nixos/hardware-configuration.nix ./hardware-configuration.nix
```

On a fresh installation using `/mnt` as the target root:

```bash
sudo nixos-generate-config --root /mnt
cp /mnt/etc/nixos/hardware-configuration.nix ./hardware-configuration.nix
```

Review the generated file before applying the configuration.

---

## 3. Review machine-specific settings

Before running `nixos-rebuild`, review at least:

```text
hardware-configuration.nix
modules/users.nix
modules/networking.nix
modules/nvidia.nix
flake.nix
```

In particular, check:

- username
- hostname
- timezone
- keyboard layout
- GPU
- filesystem configuration
- disk UUIDs
- swap devices
- host name defined in `flake.nix`

---

## 4. Check the flake

From the repository root:

```bash
nix flake check
```

You can also test the configuration without switching to it:

```bash
sudo nixos-rebuild dry-build --flake .#nixos
```

This helps catch evaluation and build errors before applying the configuration.

---

## 5. Apply the configuration

```bash
sudo nixos-rebuild switch --flake .#nixos
```

The `nixos` host corresponds to:

```nix
nixosConfigurations.nixos
```

in `flake.nix`.

---

# 🔄 Updating the System

First update the flake inputs:

```bash
nix flake update
```

Then test the configuration:

```bash
sudo nixos-rebuild dry-build --flake .#nixos
```

Finally apply it:

```bash
sudo nixos-rebuild switch --flake .#nixos
```

NixOS creates a new system generation when the configuration is switched, allowing previous configurations to remain available for rollback.

---

# ↩️ Rolling Back

List the available system generations:

```bash
sudo nix-env --list-generations --profile /nix/var/nix/profiles/system
```

You can also reboot and select an older generation from systemd-boot.

To switch back to the previous generation:

```bash
sudo nixos-rebuild switch --rollback
```

---

# 🧹 Cleaning the Nix Store

To remove old generations:

```bash
sudo nix-collect-garbage -d
```

> **Warning:** this removes old generations and can remove the configurations you would otherwise use for rollback.

You can check the size of the Nix store with:

```bash
du -sh /nix/store
```

# 🏠 Home Manager

This configuration **currently does not use Home Manager**.

Packages and system configuration are managed directly through NixOS, primarily using:

```nix
environment.systemPackages
```

User-level services can also be declared directly from NixOS modules. For example, Tachidesk uses:

```nix
systemd.user.services.tachidesk
```

Therefore, Home Manager is not required to use this repository.

If Home Manager is added in the future, it would make sense to clearly separate:

- system configuration → NixOS
- user packages/configuration → Home Manager
- Hyprland visual configuration → dotfiles

For now, the repository is intentionally designed to work without Home Manager.

# 📌 Recommended Workflow

For normal configuration changes:

```bash
# 1. Edit the configuration
$EDITOR modules/some-module.nix

# 2. Check the flake
nix flake check

# 3. Test the build
sudo nixos-rebuild dry-build --flake .#nixos

# 4. Apply the configuration
sudo nixos-rebuild switch --flake .#nixos

# 5. Check for failed services
systemctl --failed
```

For hardware changes or when moving the configuration to another machine:

```bash
sudo nixos-generate-config
cp /etc/nixos/hardware-configuration.nix ./hardware-configuration.nix
nix flake check
sudo nixos-rebuild dry-build --flake .#nixos
sudo nixos-rebuild switch --flake .#nixos
```

To update dependencies:

```bash
nix flake update
sudo nixos-rebuild dry-build --flake .#nixos
sudo nixos-rebuild switch --flake .#nixos
```

## 🗂️ Configuration Philosophy

The main goal is to keep `configuration.nix` small and organize the system into independent modules:

```text
configuration.nix
       │
       ├── hardware
       │    └── hardware-configuration.nix
       │
       ├── system
       │    ├── boot
       │    ├── networking
       │    ├── audio
       │    ├── nvidia
       │    └── users
       │
       ├── desktop
       │    ├── KDE
       │    └── Hyprland
       │
       ├── programs
       │    ├── terminal
       │    ├── gaming
       │    ├── browsers
       │    ├── development
       │    ├── media
       │    ├── Steam
       │    └── Suwayomi
       │
       └── services
            └── Flatpak
```

This means that adding or removing software usually only requires changing the corresponding module instead of turning `configuration.nix` into one large file.
